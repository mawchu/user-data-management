# 0015 釘選改成個人設定，由前端合併

- 狀態：採用（取代 [0008](0008-pinning-rules.md) 的「後端合併」）
- 階段：4 畫面

## 背景
原本釘選存在後端，由後端合併好再回傳，前端只負責 `reload()`。這樣有兩個問題：
- 釘選後畫面會跳回頂端，已載入的資料也全部丟掉。
- 題目設定 50 人同時使用，一個人的釘選會影響其他 49 個人的畫面。

確認過需求：釘選是個人設定。

## 決策
- 存在 localStorage，格式是 `[id, 位置][]`（`src/composables/usePinnedRows.ts`）。開啟頁面時用 `GET /api/users/:id` 取回釘選列的最新資料，已經被刪除的就移除。
- 合併由前端負責（`src/utils/placePins.ts`）。後端回傳的 rows 是全域排序後的前 N 筆，在這 N 筆裡依位置插入，結果也是全域正確的。換排序時後端給新的順序，前端再合併一次，釘選列就還在原本的位置。
- `displayRows` 是一個 `computed`：已載入的資料 + 釘選列。釘選、取消釘選只改 `pins`，不重新查詢。
- 沿用 0008 的規則：位置還沒載入到時先不顯示，資料全部載完就排在最後；不符合搜尋條件的不顯示（判斷規則和後端共用 `src/utils/match.ts`）；同一個位置只能釘一筆。

## 代價
- 換裝置或清除瀏覽器資料，釘選就沒了。
- 每次載入新的一批或換排序，都要把已載入的資料重新合併一次，成本是 O(已載入筆數)。沒有釘選時直接回傳原陣列，沒有額外成本。

## 驗證
- `tests/pinned-rows.test.ts`：用 5 筆資料驗證三種排序的合併結果；釘選後不重新查詢，換 3 種排序後仍然在第 2 列；localStorage 讀寫、重開頁面時移除已刪除的釘選、編輯和刪除的同步。
- e2e：釘選後捲動位置不變；切換 Age、User name、Date Start 的升降冪後仍在第 3 列；重新整理頁面後仍在。
