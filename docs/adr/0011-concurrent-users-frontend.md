# 0011 50 人同時使用時，前端要做的事

- 狀態：部分完成。第 2 點見 [0010](0010-mock-fetch-abort.md)、[0014](0014-request-lifecycle.md)；第 3 點見 [0016](0016-create-and-conflicts.md)。第 1 點「只保留最近約 10 批」仍是提議，尚未實作
- 階段：6 延伸題

## 背景
延伸問題：要能讓 50 人同時使用，而且不要佔太多 RAM。這是前端職缺，所以從前端的責任範圍來回答。後端的部分（共用排序索引、每人只記游標）只在討論中提過。

## 提議
1. **每個瀏覽器的記憶體**
   - 已完成：虛擬捲動、`shallowRef`。
   - 待做：已載入的資料只保留最近約 10 批（5,000 筆），往回捲時重新抓取。
2. **不要讓 50 個前端把 API 打爆**
   - 已完成：搜尋防抖、每批 500 筆、AbortController。
   - 待做：相同的查詢條件在短時間內直接用快取。
3. **多人同時修改的衝突**
   - 待做：每筆資料加 `version` 欄位，更新時帶上去。伺服器的版本不一樣就回 409，前端提示「這筆資料已被其他人修改」，並顯示最新內容。
   - 待做：要刪的資料已經被別人刪了（404），前端提示後把那一列移除。

## 備註
目前的 demo 在每個分頁各自產生一千萬筆（約 180MB），這是 mock 的成本。接上真 API 之後，每個分頁只需要幾 MB。
