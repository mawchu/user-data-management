# 0007 自己實作虛擬捲動

- 狀態：**被 [0012](0012-dom-recycling.md) 取代**（本文保留原樣，作為 v1 的決策紀錄）
- 階段：4 畫面

## 背景
使用者往下捲，已載入的資料會從 500 筆變成好幾萬筆。如果每一筆都產生 DOM，畫面會越來越卡。

## 決策
在 `UserTable.vue` 自己實作虛擬捲動，約 30 行：
1. 每列固定高 44px，所以 `start = Math.floor(scrollTop / 44)` 就能換算出目前捲到第幾列。
2. 只渲染從 `start` 到畫面底部的列，上下各多留 8 列緩衝，總共約 25 個 DOM 列。
3. 外層撐出「全部列數 × 44px」的高度，讓捲軸長度正確；可見的那一段用 `translateY` 移到正確位置。
4. 列表用 `shallowRef`，避免幾萬筆資料都被轉成響應式物件。更新時換成新陣列，子元件的 props 才偵測得到變化。

## 放棄的選項
Vuetify 的 `v-data-table-virtual`、`vue-virtual-scroller`：
- 它們支援不固定的列高，表頭、無障礙等細節也是內建的。
- 但為了一個元件引入整套 UI 框架不划算；無限捲動、釘選也都要配合它們的 API。
- 如果團隊已經在用 Vuetify，就改用它。原理相同。

## 代價
- 只支援固定列高。
- 瀏覽器有捲動高度上限（約 3,300 萬 px，大約 75 萬列）。

## 驗證
e2e 測試：已載入 500 筆時，DOM 只有 25 列。
