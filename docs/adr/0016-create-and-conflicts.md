# 0016 新增資料；多人修改用版本號偵測衝突

- 狀態：採用（實作 [0011](0011-concurrent-users-frontend.md) 第 3 點）
- 階段：4 畫面

## 背景
- 題目第 i 項要求新增資料，之前漏做了。
- 題目設定 50 人同時使用。原本更新是「最後送出的人直接覆蓋」：A、B 同時編輯同一筆時，A 的修改會被 B 默默蓋掉，而且沒有人知道。

## 決策
**新增**
- 表單沿用編輯視窗，前端驗證規則和後端共用。
- 新增成功後放在列表最上面，標示「新增」，並捲回頂端讓使用者看到。新資料不一定排在全域排序的前段，所以下一次重新查詢時，才會依排序規則放到正確位置。
- 之後的批次如果也有這筆，就略過不顯示，避免重複出現（`loadMore` 用 `newIds` 過濾）。

**衝突**
- 每筆資料加上 `version`，更新時帶上前端讀到的版本，後端版本不同就回 409，並附上目前的資料。
- 前端收到 409：列表先換成最新內容，再開「其他人改成 / 你要改成」的比較視窗，讓使用者選擇放棄、重新編輯，或用自己的版本覆蓋（帶最新的版本號再送一次）。
- 收到 404（已被別人刪除）：無論是更新還是刪除，都從列表移除，並提示使用者。

## 放棄的選項
- **即時推送**（WebSocket，伺服器主動通知其他人資料有變動）：題目沒有要求即時同步，而且要多一套連線管理。版本號已經能保證不會默默覆蓋。

## 代價
- 別人的修改要等自己操作那一筆、或重新查詢時才會看到。

## 驗證
- `tests/use-user-list.test.ts`：新增後在第 1 列且不重複；409 時列表換成最新內容，覆蓋後成功；404 時更新或刪除都會從列表移除。
- e2e：新增時的必填檢查；新增成功後在第 1 列並標示「新增」。
