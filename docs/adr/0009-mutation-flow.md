# 0009 刪除與更新：確認視窗、原地更新、標記刪除

- 狀態：採用
- 階段：4 畫面

## 背景
需求：刪除和更新都要有確認視窗。另外討論過一個問題：從陣列中間修改資料，效能會不會很差？

## 決策
- **確認流程**：刪除是「確認視窗 → 呼叫 API」。更新是「表單 → 下一步 → 確認視窗列出改前與改後 → 呼叫 API」。後端驗證失敗（422）時，回到表單並標出錯誤欄位。
- 用原生 `<dialog>` 的 `showModal()`：焦點鎖定、Esc 關閉、背景遮罩都是內建的。
- **更新是原地覆寫**：資料以 id 當索引，改年齡就是直接覆寫那一格，O(1)。改過的列先留在原位，下次重新查詢時才依新值排序，以免列突然跳走、使用者找不到。
- **刪除只做標記**：mock 資料庫用 `deleted` 旗標，讀取時跳過，O(1)。
- 新增資料、多人同時修改的衝突處理見 [0016](0016-create-and-conflicts.md)。

## 中間刪除的成本（實測）
| 位置 | 陣列多長 | 刪除中間一筆 |
|---|---|---|
| 前端已載入的列 | 約 5,000 筆 | 0.07ms |
| 前端已載入的列 | 10 萬筆 | 0.45ms |
| mock 的查詢快照 | 1,000 萬筆 | 3.3ms（後來改成 keyset cursor，快照不再搬移，見 0013） |

目前不構成問題。如果 n 再變大，可以：
- 讓快照也改用「標記刪除，讀取時跳過」。
- 把變更先放在旁邊的小清單，讀取時再合併（LSM tree 的思路）。

前端曾考慮用 `Map<id, 位置>` 取代 `findIndex`，但在 5,000 筆的規模下只省 0.02ms，反而多一份要同步維護的狀態，所以不做。
