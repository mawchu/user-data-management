# 0005 計數排序；搜尋先比對字典再查表

- 狀態：採用
- 階段：3 千萬筆資料層

## 背景
需求：所有欄位都能排序和搜尋，資料量是一千萬筆。

## 決策
- **排序用計數排序（counting sort）**：先數出每個值有幾筆，再依累計位置一次放好，時間是 O(n)。這能成立，是因為每欄的不同值很少：年齡 46 種、職位 12 種、日期約 6,000 種。字串欄位先依字母順序算出每個字典編號的名次，再用名次來排。這是穩定排序，同值時維持 id 由小到大。
- **搜尋**：關鍵字不分大小寫、部分符合任一欄位。先在每欄的字典裡比對一次（每欄只有幾十到幾千種值），產生一張 `[1, 0, 1, ...]` 的命中表。接著掃一千萬列時，每列只查表，不碰字串。
- 前端搜尋框加 300ms 防抖（debounce），停止輸入後才查詢。

## 實測（npm run perf，Node 22，1,000 萬筆）
- 產生資料：348ms
- 排序：189 到 450ms
- 搜尋：85 到 173ms
- 刪除一筆並更新快照：22ms
- 記憶體：約 183MB（含兩條 40MB 的排序暫存區）

## 討論過、尚未實作的優化
- 快取每欄的排序結果（每欄 40MB）：第二次排序同一欄幾乎 0 秒。
- 搜尋加排序時，直接沿著快取好的排序結果篩選，不必再排一次。
- 第一批湊滿 500 筆就先回傳，總筆數在背景另外算。
