# 0003 cursor 分頁，每批 500 筆，無限捲動

- 狀態：採用（取代 [0002](0002-page-based-pagination.md)）
- 階段：2 載入方式

## 背景
需求：每次載入 500 筆，使用無限捲動。

## 決策
- `GET /api/users?q=&sortBy=&order=&cursor=&limit=500`，回傳 `{ data, nextCursor, hasMore, total }`。
- cursor（游標）是「下一批從哪裡接著拿」的記號，由後端產生，前端原樣帶回去，不解讀它的內容。
- 在 mock 裡，cursor 是「查詢結果快照」中的位置。同一次查詢的後續批次都沿用同一份快照，所以捲動途中資料不會跳動。
- 刪除一筆時，前端把它從畫面移除，同時把 cursor 往前移一格；mock 也從快照移除同一筆。這樣下一批不會漏資料。
- 捲到離已載入資料的底部剩不到 150 列時，就先載入下一批。

## 放棄的選項
- 頁碼分頁：見 0002。
- cursor 直接用「上一批最後一筆的 id」：這只在依 id 排序時成立。一旦可以依任意欄位排序就不能用了。真實後端會改用 keyset，也就是「排序值加 id」。

## 代價
- 不能直接跳到指定頁。
- 快照要佔記憶體（見 0004 的數字）。

## 驗證
`tests/db.test.ts`：把所有批次接起來，剛好是全部資料，沒有重複；刪除後繼續捲動，也不會漏資料或重複。
